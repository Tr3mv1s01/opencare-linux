# OpenCare — Beta 0.0.1

**Значок, название приложения и понятные действия — без списка системных библиотек.**

OpenCare — бесплатный open-source инструмент обслуживания Linux с русским интерфейсом для начинающих. Независимая Linux-альтернатива основным инструментам Reg Organizer: очистка, управление установленными приложениями и автозагрузкой, настройки рабочего стола и отмена изменений.

**Это первая публичная бета-версия.** Совместимость и функции ещё развиваются. Начните с проверки: она ничего не удаляет.

## Скачать и запустить

1. Откройте [последний бета-релиз](https://github.com/Tr3mv1s01/opencare-linux/releases).
2. Скачайте `OpenCare-Linux-0.0.1-beta.1.zip` и распакуйте его.
3. Откройте терминал в папке `opencare` и выполните:

```sh
sh run.sh
```

Нужны **Linux, Python 3.10+, Tk 8.6 и графическая сессия**. Сторонние Python-пакеты, аккаунт и подписка для обычной работы не требуются. Для настоящих системных значков используется PyGObject/GTK, если он установлен; иначе отображается нейтральный значок.

Если отсутствует `tkinter`, установите его из репозитория своего дистрибутива:

```sh
# Linux Mint / Ubuntu / Debian
sudo apt install python3-tk
# Fedora
sudo dnf install python3-tkinter
# Arch
sudo pacman -S tk
```

**Сам OpenCare запускайте без sudo.**

Из исходников:

```sh
git clone https://github.com/Tr3mv1s01/opencare-linux.git
cd opencare-linux
sh run.sh
```

## Первый запуск

- На главной нажмите **«Проверить компьютер»**. Файлы и настройки останутся без изменений.
- Выберите **«Посмотреть временные файлы»** или **«Посмотреть запуск программ»**.
- Перед каждым изменением прочитайте подтверждение. Если сомневаетесь, отмените его.
- Кнопка **«Как пользоваться?»** объясняет текущий раздел по шагам.
- Для отмены откройте **«Вернуть изменения»**, выберите действие и нажмите **«Отменить действие»**.

## Что важно знать

### Очистка и возврат

Выбранные файлы перемещаются в хранилище OpenCare, чтобы их можно было вернуть. **Пока копии на том же диске, место не освобождается.** После проверки результата их можно отдельно удалить навсегда в разделе «Вернуть изменения». Это действие необратимо.

Данные хранятся локально в `$XDG_STATE_HOME/opencare`, обычно `~/.local/state/opencare`. Папка создаётся с правами 0700; копии могут содержать личные данные. В программе нет телеметрии и отправки файлов.

### Удаление приложений

OpenCare связывает ярлык приложения с установленным DEB, Flatpak или Snap. Если связь не подтверждена, приложение видно, но удаление блокируется с пояснением. Для известных ключевых компонентов рабочего стола и системного управления удаление через GUI также отключено.

Удаление выполняется штатным менеджером пакетов в терминале. Он показывает итоговый список изменений и запрашивает подтверждение; при вводе пароля символы могут не отображаться. Удаление программ **не отменяется** журналом OpenCare. Менеджер пакетов может использовать сеть в рамках своей обычной работы.

На RPM/Arch меню приложений читается, но сопоставление ярлыков с системными пакетами пока не реализовано: удаление таких приложений из GUI недоступно. Системные пакеты не подставляются вместо приложений при пустом результате.

### Рабочий стол и автозагрузка

Linux не использует реестр Windows. Его функции здесь заменены пользовательскими файлами настроек и сравнением состояния папок. Дефрагментация реестра Windows неприменима; ускорение компьютера не обещается.

Настройки выбираются по активному рабочему столу: Cinnamon/Nemo либо GNOME. На KDE/Xfce переключатели пока не поддерживаются. Ошибки записи dconf отображаются как ошибки, даже если системная команда вернула код 0.

Автозагрузка охватывает XDG Autostart, а не службы systemd и все остальные механизмы запуска. Уже работающая программа при отключении автозагрузки не закрывается.

### Границы поддержки

- Пользовательские файлы: системные каталоги, ядра и данные других пользователей не очищаются.
- История Chromium/Chrome и список недавних документов XDG поддерживаются отдельно от кэша. Браузер нужно закрыть; базы с SQLite WAL/SHM/journal пропускаются.
- История Firefox не очищается, поскольку её база также содержит закладки. Пароли, cookies и закладки не удаляются.
- Редактор поддерживает UTF-8 до 1 МиБ и сохраняет предыдущую версию. Внешние изменения не перезаписываются при сохранении или восстановлении.
- Сравнение папок хранит метаданные и хэши, **а не содержимое файлов**. Это не резервная копия компьютера. Для файлов свыше 10 МиБ сравниваются только размер и время.
- Символические ссылки при изменении файлов не обходятся. Сканирование ограничено 150 000 файлами, поиск конфигураций — 50 000; пропуски сообщаются.
- Папки с похожими именами не считаются доказанными остатками приложений. В ядре сохранён инструмент такого поиска для ручной проверки.

## Разработка

```sh
python3 -m unittest discover -s tests -v
# Для графического теста нужен доступный дисплей:
python3 tests/gui_smoke.py
# Собрать исходный ZIP:
python3 packaging/build_release.py
```

В поставке 26 модульных тестов и изолированный GUI-сценарий. Для CI приложен [шаблон GitHub Actions](docs/ci/github-actions-tests.yml): модульные тесты на Python 3.10/3.12/3.13 и GUI через виртуальный дисплей. Чтобы включить его, поместите файл в `.github/workflows/tests.yml`. Границы фактической проверки описаны в [отчёте](docs/VERIFICATION.md).

Опциональные локальные интеграционные проверки:

```sh
python3 tests/host_gui_check.py
python3 tests/machine_check.py
```

Они читают реальные данные текущей системы. Флаг `--toggle-settings` для `machine_check.py` реально кратковременно меняет и восстанавливает параметры рабочего стола: используйте его только осознанно. Для точного восстановления пользовательских переопределений этому тесту нужен системный PyGObject (`gi`).

Технический CLI также поддерживает `info`, `scan`, `packages`, `startup`, `journal`, `snapshot`. Запуск без подкоманды открывает GUI.
